# 版本批注与审阅协议

## 目标

让审阅意见稳定绑定到工作区版本、Git commit 或 Markdown 内容块，同时不修改笔记正文和 commit。同步是可选增强，本地路径始终可用。

## 本地模型

每条批注保存仓库根、当前 Vault 路径、历史路径、版本标识、目标类型、意见、状态与时间。内容块额外保存内容指纹、Markdown 类型、标题路径、原始行号和受限的原始上下文。

状态只有三种：

- `pending`：待处理；
- `resolved`：已解决；
- `wont-fix`：确认无需处理。

插件数据 schema v6 最多保存 1,000 条批注、每篇笔记 200 条、每条意见 4,000 字符。加载时隔离无效记录，文件或文件夹重命名时同步迁移当前 Vault 路径。

## 内容块重定位

先在当前正文中寻找相同内容指纹；找不到时，再使用 Markdown 类型、标题路径与文本相似度进行保守匹配。只有得分至少 0.55 才认定为已重定位，否则显示“原块未找到”，继续保留创建批注时的上下文，绝不静默绑定到低置信度内容。

## Markdown 审阅包

审阅台可复制一个独立 Markdown 文档，包含文件、生成时间、状态、完整 commit、历史路径、块位置、标题路径、意见与原始上下文。它只进入剪贴板，不会自动在 Vault 内制造文件。

## 可选 Git notes

只有绑定真实 commit 的批注能写入 `refs/notes/git-note-history-review`。写入前必须再次确认：

- Git notes 不改 commit 对象或笔记正文；
- 普通 `git push` 默认不会同步 notes；
- 插件仅替换 `<!-- git-note-history:begin -->` 与 `<!-- git-note-history:end -->` 之间的 JSON；
- 同一 note 的其他人工文字保持原样；
- 合并按批注 ID 和 `updatedAt` 选择更新记录。

插件不自动 push、fetch、配置 remote 或修改默认 notes ref。

## 入口

- 命令：打开当前笔记的版本批注；
- 命令：批注当前笔记的工作区版本；
- 编辑器命令：批注当前段落或选中内容块；
- 历史版本“更多”菜单：批注这个历史版本；
- 文件菜单与历史侧栏快捷入口。

## 安全边界

本地保存、状态更新和 Markdown 导出不执行 Git 写操作。Git notes 是唯一 Git 写路径，使用专用 ref、用户确认和受控标记；不执行 commit、checkout、reset、push 或分支切换。
