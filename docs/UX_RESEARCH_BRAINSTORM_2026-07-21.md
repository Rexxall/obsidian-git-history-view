# Git Note History 交互研究与第二轮头脑风暴

日期：2026-07-21
基线：v0.3.3
状态：研究与规划。文中的下一轮推荐四项已在 v0.4.0 完成第一版；“更大的创意池”和各项继续增强仍不代表已经实现，以 `ROADMAP.md` 的勾选状态为准。

## 一句话结论

下一阶段不应继续把插件做成“小型 Git 客户端”，而应把它收束成 Obsidian 原生的“笔记审阅与恢复工作台”：

1. 先告诉用户哪些变化值得看；
2. 再帮助用户快速理解变化发生在哪里、意味着什么；
3. 最后让恢复操作可预测、可追踪、可多次撤销。

主流程应从现在的“选择版本 → 选择一种查看模式”升级为：

> 发现待复查变化 → 选择有意义的时间点 → 沿变化导航 → 预演恢复结果 → 恢复并保留回执

## 对当前 v0.3.3 的判断

### 已经形成的优势

- Git 原始内容边界清楚，不会自动移动 HEAD、提交或暂存。
- 时间滑杆、段落历史、链接影响和三方冲突解决已经覆盖了普通同类插件没有覆盖的 Markdown 语义。
- 整篇与局部恢复有并发修改保护和一次撤销。
- 侧栏与中央详情页已经分开，专注模式也能正确恢复 Obsidian 布局。
- 相同内容和相同关系已有明确空状态，不再用大片空 Diff 冒充结果。

### 当前最影响体验的四个问题

1. **侧栏层级仍然过多。** 搜索、当前工作区、时光机、双版本选择和完整提交列表同时存在，用户第一次打开时不知道先看哪一个。
2. **版本等于 commit，而不是“有意义的编辑阶段”。** 自动备份会制造大量相邻且近似的提交，时间线可用但不够可读。
3. **五种查看模式并列暴露。** “并排 / 统一 / 预览 / 语义 / 关系”是实现分类，不完全是用户任务分类。
4. **恢复虽然安全，但安全感不够可见。** 当前只有一次撤销，没有结果预演、影响摘要、恢复历史和明确的“撤销什么”。

## 新的交互架构

### 第一层：快速历史（右侧栏）

只回答三个问题：

- 现在有没有值得注意的变化？
- 自上次确认后发生了什么？
- 我应该从哪个时间点开始看？

默认只显示：当前状态、一张“自上次确认”摘要卡、有效版本组。搜索、播放、任意双选、作者和 hash 等进入“更多”或中央工作台。

### 第二层：审阅工作台（中央页）

只回答三个问题：

- 变化发生在哪里？
- 这次变化改变了内容、结构还是知识关系？
- 我需要复制、局部恢复还是整篇恢复？

默认布局使用一条变化地图和一块主内容区。查看模式从五个并列按钮改为两个任务入口：

- **读变化**：默认使用适应宽度的 Diff，内含“原文 / 渲染后”切换；
- **看影响**：结构、属性、任务、链接和断链风险集中到检查器。

高级用户仍可在“视图选项”中明确选择并排、统一、Markdown 双预览等底层模式。

### 第三层：恢复安全中心（操作流程）

只在用户准备修改文件时出现，负责：

- 明确恢复范围和目标时间；
- 预演恢复后的最终内容；
- 检查 Frontmatter、链接、附件引用和并发修改；
- 创建自动快照；
- 生成可查看、可连续撤销的恢复回执。

## 下一轮推荐四项

以下四项是本轮研究产生的 v0.4 范围，现已完成第一版；每节中超出 `ROADMAP.md` 已实现说明的延伸能力仍属于后续规划。

### 1. 复查收件箱：自上次确认后发生了什么

#### 要解决的问题

用户通常不是想“浏览全部 Git 历史”，而是想知道自己上次看完以后有哪些东西需要确认。

#### 核心交互

- 每篇笔记保存一个本地 `reviewCheckpoint`，不写进笔记正文和 Git。
- 侧栏第一张主卡显示：`自 7 月 18 日确认后：3 个有效版本，+42 / −11，2 个标题变化，1 个链接移除`。
- 点击主卡直接打开 checkpoint → 当前工作区的综合审阅。
- 审阅完成后使用单一主按钮“标记已复查”；旁边提供“仅标记到此版本”。
- 增加全库“待复查”入口，但默认不常驻侧栏。
- 支持“稍后看”和固定重要变化，不把它们伪装成 Git commit 状态。

#### 视觉

- 未复查使用克制的强调色圆点，不用大面积警告红。
- 删除、断链和冲突才使用危险色。
- 卡片完成后收起为一行“已复查到 2 小时前”。

#### 验收

- 从打开历史到看到“上次以后发生了什么”不超过一次点击。
- 标记已复查不修改 Git、笔记或暂存区。
- 文件重命名后 checkpoint 仍能通过仓库根目录和历史路径稳定匹配。

### 2. 有效版本：自动聚合备份噪音与智能比较

#### 要解决的问题

频繁自动提交会让 100 个 commit 看起来像 100 个重要版本，时光机的信噪比随使用时间下降。

#### 核心交互

- 默认按“编辑会话”聚合相邻提交，例如在短时间内、同一作者、同一文件且变化连续的 commit 折成一组。
- 完全相同内容直接去重；仅空格变化归入低优先级；只改元数据可显示为“属性调整”。
- 每组生成确定性摘要，不依赖 AI：`重写「研究问题」；新增 2 个链接；完成 3 个任务`。
- 节点大小表达有效改动规模，特殊形状标出重命名、删除、冲突、人工标签和 review checkpoint。
- 默认点击组与“组开始前”比较；展开后仍可选择任一原始 commit。
- 增加智能比较菜单：`与上次确认比较`、`与上一有效版本比较`、`与当前工作区比较`、`与固定基线比较`。

#### 视觉

- 时间线主节点只表达重要程度，不同时塞作者、hash、日期和所有 trailer。
- 细节在悬停、键盘聚焦或展开时出现。
- 自动播放仅播放有效版本，原始 commit 播放放进选项。

#### 验收

- 聚合是视图层行为，不改变 Git 历史。
- 用户可以一键切换“有效版本 / 原始提交”。
- 聚合规则和每组包含哪些 commit 均可解释、可展开。
- 1000 个原始提交的列表不能一次创建 1000 个完整 DOM 卡片。

### 3. 变化地图：标题级小地图、差异导航与块年龄镜头

#### 要解决的问题

当前 Diff 能展示变化，却不能快速回答“长笔记的哪些章节变化最大”和“这段内容从什么时候开始存在”。

#### 核心交互

- 审阅页顶部固定显示 `变化 3 / 12`，支持上一个、下一个变化。
- 左侧或页面边缘显示按 Markdown 标题划分的细长变化地图；块高度近似章节长度，颜色和图标表达增、删、移动、属性或链接变化。
- 点击地图跳到对应标题，并在两侧同步滚动。
- 未变化区域默认折叠，可单独展开，也可全局“显示上下文”。
- 在普通笔记编辑器中提供临时“内容年龄镜头”：以标题或段落块为单位显示最近修改时间；悬停显示首次出现、最近修改和对应版本。
- `Esc` 退出镜头，关闭后不留下永久装饰。

#### 视觉与无障碍

- 不能只靠红绿区分；同时使用 `+ / − / ↔`、线型或纹理。
- 地图、差异列表和主内容共享选中状态，键盘焦点始终可见。
- 提供类似统一 patch 的无障碍阅读模式，差异按顺序朗读。

#### 验收

- 长笔记可以只用键盘从第一处变化走到最后一处。
- 点击变化地图后，标题和目标差异不会被固定工具栏遮挡。
- 仅移动的段落不应被误报成一整段删除加新增。
- 窄于设定宽度时自动使用统一布局，不产生横向滚动迷宫。

### 4. 恢复安全中心：结果预演、多步撤销与恢复回执

#### 要解决的问题

“会自动备份”是一句承诺；用户真正需要看到恢复会改什么、刚才改了什么、下一次撤销会撤销什么。

#### 核心交互

- 恢复按钮改为菜单：`恢复此变更块`、`恢复此段落`、`恢复整篇`、`另存为副本`。
- 危险操作打开预演弹窗，首先展示范围、目标版本、预计增删、结构变化和关系风险。
- 弹窗默认焦点在“取消”或“另存副本”，而不是危险确认按钮。
- 恢复前自动保存带时间和动作名称的快照，例如：`恢复「方法」段落前的版本`。
- 支持有限但多步的撤销栈，而不是全插件只有一次撤销。
- 恢复完成后打开结果位置并短暂高亮，同时显示回执：文件、范围、来源 commit、执行时间、结果 hash、是否已被后续编辑。
- Toast 明确写成“撤销：恢复「方法」段落”，而不是泛化的“撤销上次恢复”。
- 如果后续编辑导致无法安全自动撤销，仍保留回执和“打开恢复前副本”，不把记录直接变成不可用。

#### 验收

- 任何写回操作都必须经过同一恢复服务和并发保护。
- 整篇、块、段落恢复均可在执行前看到最终结果。
- 连续做三次恢复后，可按相反顺序安全撤销三次；一旦内容发生外部修改，插件必须解释停止在哪一步。
- 弹窗满足焦点陷阱、`Esc` 关闭、关闭后焦点返回触发按钮。

## 更大的创意池

以下创意继续保留，但不应和下一轮四项同时开工。

### 更容易上手

- **首次运行检测页**：Git 是否可用、仓库根目录、当前分支、笔记是否被跟踪、可读取的历史数量。
- **空状态带下一步**：未跟踪时解释“历史从第一次 commit 后开始”，并给出复制命令，不自动执行。
- **任务式命令面板**：用“看看最近改了什么”“找回删除内容”“追溯这段话”替代纯 Git 术语。
- **三分钟引导**：用一篇临时演示笔记展示查看、比较、恢复和撤销，不污染真实笔记。
- **上下文入口统一**：文件菜单、编辑器标题菜单、段落右键、命令面板都进入相同请求模型。

### 更快找到版本

- 日历和活动热力图，但只作为筛选器，不另造主导航。
- 按内容搜索历史，而不只搜索 commit message、作者和标签。
- 自然时间筛选：今天、昨天、上周、上次打开前、上次发送前。
- “第一次出现”与“最后一次存在”搜索，帮助找回后来被删除的句子。
- 版本标签支持颜色、说明和状态，但保持本地存储。
- 文件重命名轨迹以面包屑展示，而不是只在底层默默 `--follow`。

### 更容易看懂 Markdown 变化

- YAML 属性以字段为单位展示，数组按成员变化展示。
- 标题层级变化与纯文本修改分开。
- 任务状态演变显示为 `待办 → 完成 → 重新打开`。
- 表格按行列和单元格比较，避免整表变红变绿。
- Callout、代码块、公式、Mermaid、脚注和嵌入按块比较。
- 提供“忽略格式变化”，覆盖空格、换行、列表符号与属性排序。
- 对大规模格式化 commit 提供“低价值变化”标记，允许临时隐藏。
- 对段落移动显示来源箭头，而不是重复的删除和新增。

### 更适合知识库

- 恢复前显示会重新引入的断链和已不存在附件。
- 标题或文件名变化前后显示反链影响。
- 关系变化按“链接、嵌入、标签、附件、脚注”筛选。
- 显示某个概念第一次进入、被重写、被删除和重新引入的时间。
- “知识关系没有变化”保持简短，不渲染无意义大图。
- 支持将某次关系变化另存为 Markdown 审阅记录。

### 更适合长期复查

- 全库复查收件箱按风险排序：冲突、删除、断链、大幅删减、普通修改。
- 审阅状态：待看、已确认、稍后看、忽略此次；状态不进入 Git。
- 按日或编辑会话生成“今天改了什么”，而不是逐 commit 流水账。
- 审阅完成率只做辅助，不设计成制造焦虑的打卡系统。
- 审阅报告可导出 Markdown；PDF 延后到 Markdown 稳定后。
- 对自动备份 commit 允许批量确认，但危险事件必须单独确认。

### 更好看但不喧宾夺主

- 采用 Obsidian CSS 变量，不固定背景色、字体和阴影。
- 卡片只保留一层边界；选中项用细边、轻底色和节点三者之一，不三者叠加。
- 时间线节点大小表达改动规模，形状表达事件类型，颜色只表达状态。
- 动画只用于定位恢复结果、时间滑动和折叠展开，并尊重 `prefers-reduced-motion`。
- 侧栏密度由可用宽度自动适配，而不是只靠设置项。
- 所有图表提供文字摘要；图表不是唯一信息载体。
- 暗色主题降低纯红纯绿饱和度，避免大片发光背景。

### 更可靠、更快

- Git 请求增加取消与最新请求获胜，快速切换笔记不会让旧结果覆盖新结果。
- 缓存 commit 元数据和已读取内容；相邻有效版本预取，远端版本按需加载。
- 时间线使用窗口化列表；大历史分段加载，保留稳定滚动位置。
- Diff 计算放到可取消任务中；先显示概要，再渐进渲染大块内容。
- 缓存键包含仓库根目录、文件历史路径、commit hash 和相关设置。
- 设置页增加“诊断”区：Git 版本、仓库、缓存大小、最后错误、复制诊断报告、清理缓存。
- 错误信息提供发生阶段、实际路径、建议操作；高级区可查看只读 Git 命令。
- 浅克隆、LFS、子模块、二进制文件和仓库损坏分别降级，不能共用一句“加载失败”。

### 谨慎探索

- **Git + File Recovery 统一时间线**：仅在有稳定、合法的公开接口或可选适配器时实现；必须清楚标出来源、保留期和可用性。
- **本地快照**：如果实现，必须与 Git 历史分层显示，并把存储位置、保留策略和 Git ignore 建议讲清楚。
- **AI 摘要**：只能建立在确定性语义摘要之上，默认关闭，可编辑，不参与恢复决策。
- **协作评论**：先做本地审阅批注和导出，不直接引入账号、云端或远程写入。
- **移动端**：优先只读浏览、复制和另存副本；系统 Git 不可用时清楚说明，不伪装成完整支持。

## 明确不建议现在做的事

- 不增加完整 branch graph、push、pull、rebase 和 remote 管理；这些由 Obsidian Git 或专用 Git 客户端负责。
- 不把五种乃至更多 Diff 模式继续平铺在主工具栏。
- 不把自动播放做成主导航；它是展示功能，不是高频审阅动作。
- 不用 AI 代替确定性 Diff、恢复预演或风险检查。
- 不依赖 Obsidian 私有 API 作为插件启动或 Git 历史浏览的必要条件。
- 不先做全库大仪表盘；先把“单篇笔记发现—理解—恢复”闭环做顺。
- 不用更多渐变、阴影和动画掩盖信息层级问题。

## 优先级建议

| 层级 | 内容 | 原因 |
| --- | --- | --- |
| P0 | 复查收件箱、有效版本聚合、智能比较入口 | 直接降低时间线噪音和第一次打开的认知负担 |
| P0 | 上/下一个差异、未变化折叠、恢复预演、多步撤销 | 直接提高审阅速度与恢复安全感 |
| P1 | 标题级变化地图、块年龄镜头、响应式 Diff、色觉模式 | 同时提升长笔记效率、视觉品质和无障碍 |
| P1 | 内容搜索、重命名轨迹、删除内容定位、恢复回执 | 强化真正的“找回内容”能力 |
| P2 | 全库待复查、日报、导出审阅报告 | 单篇闭环稳定后再扩到工作区 |
| 探索 | File Recovery 适配器、本地快照、AI、移动端 | 依赖、边界或维护成本较高 |

## 建议实施顺序

1. 先定义 `ReviewCheckpoint`、`VersionGroup`、`RestoreReceipt` 三个稳定数据模型，并补迁移测试。
2. 实现确定性的有效版本聚合和智能比较，不改现有 Git 读取结果。
3. 重排侧栏，让“待复查”成为默认首要任务，原始时间线仍可展开。
4. 为现有 Diff 补统一的变化索引、前后导航、折叠状态和响应式布局。
5. 把整篇、hunk、段落写回统一到支持多步快照与回执的恢复服务。
6. 再增加变化地图和块年龄镜头；最后考虑跨来源适配和 AI。

## 可量化的体验目标

这些是后续验收目标，不是当前性能声明。

- 打开一篇已有历史的笔记后，一次点击内进入“自上次确认”审阅。
- 缓存命中时，相邻有效版本切换在 150 ms 内出现首屏反馈。
- 500 个原始 commit 聚合后，侧栏首屏只渲染可见行与少量缓冲行。
- 用户可只用键盘完成：选版本、前后差异、打开预演、取消、恢复、撤销。
- 窄侧栏、中央页、深色、浅色、色觉模式、减少动态效果均有截图验收。
- 每个写操作都能回答：改哪个文件、改哪一部分、来源是什么、能否撤销、撤销会发生什么。

## 评审问题

每次准备新增功能时，先问：

1. 它是在帮助用户发现、理解还是恢复？
2. 它是否能收进现有任务，而不是再增加一个并列模式？
3. 它在 240–320 px 侧栏中是否仍然成立？
4. 它只靠颜色能不能看懂？只用键盘能不能完成？
5. 它会不会修改 Git、笔记或暂存区？界面是否提前讲清楚？
6. 它在自动备份产生大量小 commit 时是否仍然有用？
7. 它失败时是否保留原内容、解释原因并给出可执行下一步？
