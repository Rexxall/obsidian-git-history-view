## 笔记没有历史

```text
Git Note History 没有显示我的笔记历史。请帮我定位并修复原因。
你只能查看和修改 <vault>/.obsidian/plugins/git-note-history/。如有需要，只读我指定的那篇笔记。不得访问其他插件或笔记，不得修改任何笔记。不得查看或修改该目录之外的仓库；需要 Git 或 Obsidian 信息时，让我提供输出。删除任何内容前，先停下来问我。
检查 manifest.json、已安装的插件文件，以及 data.json 中的 gitExecutable 和 repositoryRoot。让我确认使用桌面版 Obsidian 1.13 或更新、Git 是否可用，并提供侧栏的完整提示。区分缺少 Git、没有仓库、没有提交、笔记未跟踪或被忽略、已暂存但未提交，以及笔记在检测到的仓库之外。不要初始化、提交、暂存或修改忽略规则。如果缺少 Git 配置，说明需要我做什么，不要当成插件错误。
最后让我打开一篇确定有提交历史的笔记，点时钟图标、选版本、点“和当前比较”。时间线应显示这篇笔记的版本，对比应能打开。如果配置仍缺失，报告阻碍，并让我运行“看示例（不读仓库）”，应显示三个示例版本。示例能用不代表真实历史已恢复。
```

## 搜索中断或找不到旧内容

```text
Git Note History 读取历史或搜索旧内容时停止，或者找不到较早的一句话。请帮我定位并修复原因。
你只能查看和修改 <vault>/.obsidian/plugins/git-note-history/。如有需要，只读我指定的那篇笔记。不得访问其他插件或笔记，不得修改任何笔记。不得查看或修改该目录之外的仓库；需要 Git 或 Obsidian 信息时，让我提供输出。删除任何内容前，先停下来问我。
检查 data.json 中的 maxCommits（默认 100，设置允许 10–1000），以及已安装插件的历史加载、内容搜索取消和超时处理。向我索要完整提示，并问我是否手动停止过搜索。Git 命令在 120 秒后超时。区分读取上限、浅克隆、部分克隆、LFS 指针和缺失对象。不要 fetch、修复仓库、取消超时或改成无限读取。
最后让我在读取停止后点“重新读取”，再搜索一段确定在已加载历史里的文字，应找到对应版本。让我停止一次较长的搜索再重试，界面应有响应，重试应能加载结果。如果所需 Git 对象不可用，报告这个限制，不要说文字从未存在。
```

## 改名后的笔记没有旧历史

```text
Git Note History 在移动或改名尚未提交时，把我的笔记当成未跟踪文件。请帮我定位并修复原因。
你只能查看和修改 <vault>/.obsidian/plugins/git-note-history/。如有需要，只读我指定的那篇笔记。不得访问其他插件或笔记，不得修改任何笔记。不得查看或修改该目录之外的仓库；需要 Git 或 Obsidian 信息时，让我提供输出。删除任何内容前，先停下来问我。
检查 manifest.json 和已安装插件的改名识别逻辑；未提交移动的支持从 0.12.2 加入。向我询问新旧笔记的相对名称和侧栏提示。插件会使用 Git 已暂存的改名、内容完全相同的已删除笔记，或者唯一明显最相似且保留至少一半内容的已删除笔记。候选有歧义时不会猜测。不要暂存或提交移动，不要改名，不要查看授权范围外已删除的笔记。
最后让我打开指定的移动后笔记。移动关系明确时，应显示旧版本和“已改名”标记，“与最近提交比较”应使用旧路径。工作区增删行数应与旧版本比较，而不是把整篇当成新增。如果候选仍有歧义，解释为什么没有选定旧路径。
```

## 编辑后恢复或撤销被停止

```text
Git Note History 因笔记发生变化而停止恢复或撤销。请帮我判断是安全检查正常生效，还是存在错误。
你只能查看和修改 <vault>/.obsidian/plugins/git-note-history/。如有需要，只读我指定的那篇笔记。不得访问其他插件或笔记，不得修改任何笔记。不得查看或修改该目录之外的仓库；需要 Git 或 Obsidian 信息时，让我提供输出。删除任何内容前，先停下来问我。
向我索要完整提示，问我是否在打开预览后或恢复后又编辑过。检查插件的恢复核对逻辑和已保存的撤销记录，最多保留 12 步。笔记变化时停止是预期行为。保留保护检查、设置和撤销记录，不要强行写回或重置 data.json。
先让我重新打开对比和恢复预览，应反映指定笔记的当前内容。再让我在“看示例（不读仓库）”里进行内存中的恢复，示例应更新，真实笔记应保持不变。若修改了变化检测，用内存输入验证：未变化时可继续，已变化时必须停止。如果当前编辑仍阻止撤销，说明这是预期限制。
```
