# 知识图谱时间机与恢复冲击波

## 产品边界

这个功能回答两个窄而明确的问题：

1. 一篇笔记的链接、嵌入、附件、标签和脚注在哪些版本边界发生了变化？
2. 把当前笔记恢复成旧内容，会不会让当前 Vault 的反链、锚点或附件引用失效？

它不是全库知识图谱的替代品，也不根据链接数量判断内容真假。历史版本中的关系来自当时的 Markdown；目标是否存在、反链是否仍能解析，则来自恢复前的当前 Vault。

## 时间机

- 最多读取最近 80 个版本，Git commit 按路径连续历史从旧到新排列，当前工作区是最后一个明确端点。
- 相邻版本均可读时才计算关系差异；任一端不可读、超过 2 MB 或超过 500 个关系时形成间隙。
- 纯正文变化被折叠，时间轴只保留关系增删事件。
- 过滤器把 Wikilink 与 Markdown 链接合并为“链接”，同时保留嵌入、附件、标签和脚注五个用户任务。
- 播放器只是逐项选择关系事件，不修改文件、Git HEAD、分支、索引或对象库。
- 局部图最多显示 24 个变化节点；完整列表最多先渲染 30 个关系，防止异常笔记拖慢界面。
- 从事件进入详情页时使用本次采样正文，避免读取期间文件变化把旧结果悄悄替换。

## 恢复冲击波

普通恢复弹窗先显示一句风险摘要，需要时展开局部冲击波：

- 旧版将重新引入、并且在当前 Vault 可解析的关系；
- 旧版本身包含但当前 Vault 无法解析的目标；
- 旧版引用、但当前 Vault 已经不存在的附件；
- 其他笔记指向当前标题或块 ID，而旧版会移除对应锚点；
- 其他笔记通过当前别名引用，而旧版 Frontmatter 会移除该别名。

普通入站链接只要文件路径仍在就不会被夸大成风险。冲击波也不会声称能证明动态 Dataview、第三方插件查询、Canvas 内部对象或未加载 Vault 的完整影响。

## 安全与性能

- 只使用现有只读 Git 查询、Vault 读取和 MetadataCache，不写入额外索引。
- 历史内容四路并发读取；关闭或切换页面后旧结果不得覆盖新页面。
- 未知边界保持未知，不能用相邻可读版本补齐。
- 恢复仍通过原有并发校验、预览、回执和撤销流程；冲击波不会绕过确认。
