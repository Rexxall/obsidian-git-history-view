# 恢复篮子设计

## 目标

恢复篮子解决“一个完整旧版本并不是我想要的最终结果”这一类恢复任务。用户可以从多个 Git 版本挑选同一篇笔记的若干修改块或 YAML 属性，先得到一个可检查的最终 Markdown，再执行一次写回。

它不是剪贴板，也不连续修改笔记。篮子中的所有项目都相对第一项加入时冻结的当前正文定位。

## 首版范围

- 只处理同一篇 Markdown 笔记。
- 来源只接受现有 Git commit 历史。
- 可收集统一 Diff 的修改块，以及结构比较中的单个 YAML 属性。
- 允许调整审阅顺序、移除项目和清空篮子。
- 最终写回复用现有恢复服务、并发校验、回执和撤销栈。

跨文件恢复、任意手选段落、自动冲突解决和非 Git 来源留给后续版本。

## 交互流程

1. 在历史版本与当前工作区的对比中点击“加入恢复篮子”。
2. 第一项创建篮子，并冻结当前笔记正文和指纹；后续项目必须使用同一基线。
3. 从详情页、时间线或命令面板进入中央恢复篮子。
4. 工作台先展示来源与每项操作，再展示写回前检查。
5. 用户检查合并后的完整 Markdown；存在阻止项时不能应用。
6. 点击应用后进入现有恢复预演。
7. 确认瞬间重新读取笔记和篮子并重新规划，成功后只写回一次。
8. 写回成功才清空篮子；恢复回执和撤销保留完整事务。

## 冲突与提醒

阻止写回：

- 当前笔记偏离冻结基线。
- 两项修改命中重叠范围。
- 多个来源写入同一个 YAML 属性。
- 补丁失效或超过项目数、存储大小限制。

允许写回但明确提醒：

- 完全重复项目会跳过后加入的一项。
- 新增内容在多个项目中重复。
- 最终结果删除 Wikilink、Markdown 链接、嵌入或标签关系。

## 安全边界

- 不运行 checkout、reset、revert、add 或 commit。
- 不修改 HEAD、分支、索引或 Git 对象。
- 不把算法合并结果直接写回；完整最终 Markdown 必须先可见。
- 确认与实际写入之间使用期望正文校验。
- 恢复篮子只保存在插件本地数据，不写入笔记或 Git 历史。
- 单篮子最多 40 项、序列化后最多 2 MiB。

## 验收重点

- 两个不重叠的历史片段能合并为一个最终结果。
- 重叠片段和同属性多来源覆盖会阻止应用。
- 笔记在收集后发生变化会使篮子过期。
- 完全重复项目只应用一次。
- 删除关系会展示明确提醒。
- 属性恢复不替换笔记正文的其他内容。
- 重启插件后有效篮子仍存在，损坏数据不会阻止插件启动。
- 两个测试库 两个 Vault 安装文件一致，原有 `data.json` 保留。
