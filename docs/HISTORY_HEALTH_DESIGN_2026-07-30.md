# 历史信噪比与健康中心

## 产品问题

Git 中的 revision 不都代表知识变化；自动更新时间、生成字段、属性排序和格式化会淹没真正内容。同时，本地时间线也可能因为浅克隆、缺对象、读取窗口或未推送提交而不完整。健康中心把“少看噪音”和“不要误以为历史完整”放在同一页解释。

## 信噪比规则

每条已读取 revision 只会落入一种分类：

- 有效内容；
- 维护属性；
- 生成字段；
- 格式变化；
- 完全重复；
- `.git-blame-ignore-revs` 参考；
- 未知。

平衡模式只隐藏证据充分的重复、指定属性、生成字段和确定格式变化。严格模式额外折叠纯空白批量格式化。原始 Git 模式不隐藏任何 revision。

规则按 Vault 保存：

- 时间和维护属性列表；
- 自动生成属性列表；
- 是否参考 `.git-blame-ignore-revs`；
- 默认预设。

Frontmatter 只有顶层字段、正文和其他结构都一致时才会归为属性噪音。字段附近存在 YAML 注释时，该段不参与自动忽略，避免把审阅说明当作时间戳一起隐藏。无法读取的版本、超大版本和读取窗口最老的截断边界保持未知。

## 健康诊断

只读诊断检查：

- `rev-parse --is-shallow-repository`；
- promisor / partial-clone 配置；
- 当前笔记在 HEAD 可达对象中的 `--missing=print` 结果；
- 当前 Markdown 是否是 LFS 指针；
- 单篇历史是否达到读取窗口；
- upstream 是否存在，以及相对 upstream 的 ahead / behind；
- 当前工作区是否未提交；
- 插件本地快照数量；
- `.git-blame-ignore-revs` 是否可用；
- Git 对象格式。

每项都显示证据范围和人工修复建议。没有风险不等于完成仓库取证，页面会避免“健康满分”式误导。

## 边界

- 最多分析 120 条 revision；
- 单版内容最多 2 MB；
- 每批四路读取；
- 缺对象、不可读、大文件和截断均保持显式未知；
- 不执行 fetch、pull、Git LFS 下载、stage、commit、push、remote 修改、upstream 配置、checkout 或 reset；
- 点击 revision 打开冻结只读原始比较，不开放恢复动作；
- 信号过滤不改变普通 Git 时间线、commit、blame 或笔记。

## 入口与布局

- 命令：打开当前笔记的历史健康中心；
- 文件菜单：检查历史健康；
- 历史侧栏：活动脉冲图标；
- 顶部四个紧凑指标；
- 完整性诊断卡；
- 平衡 / 严格 / 原始 Git 预设；
- 当前结果 / 全部原始 / 仅噪音 / 无法判断筛选；
- revision 行点击进入准确的只读前后版本比较。
