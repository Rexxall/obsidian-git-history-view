# 来源可信度镜头设计

## 目标

可信度镜头回答三个可核对的问题：

1. 当前每个 Markdown 块最近由谁或什么流程修改；
2. Agent、自动化、脚本和工作区修改是否已经被现有人工复查点覆盖；
3. 正文表述变化时，原有引用集合是否完全没有同步变化。

它不回答内容是否正确，也不因为内容来自 Agent 就降低评价。

## 证据层

- 当前正文先被冻结，并在分析结束后再次核对内容指纹、HEAD、分支和工作区状态。
- `git blame --line-porcelain --contents -` 只读取冻结正文，不修改工作区。
- blame commit 与现有路径连续历史对齐，读取 `Agent`、`Authority`、`Send-Gate` 和 `Workflow-Status` trailer。
- untracked 内容保留为“当前工作区”；无法归属的内容保留为“未知”，不根据文字风格猜作者。
- 现有本地复查点只表示用户曾确认到哪个 commit / 工作区指纹，不等于事实审核或外部背书。

## 块与提示

- Frontmatter、标题、段落、列表、引用和围栏代码块分别形成块。
- 一个块可以有多个来源；界面按最近来源突出，同时保留每个来源的行数和 trailer 证据。
- Agent、自动化、脚本或工作区来源未被复查点覆盖时进入“待复查”。
- 当前块与上一 Git 版本的稳定位置块相比，若正文变化但已有链接、嵌入、附件或脚注集合完全相同，则显示“引用同步待核”。
- 引用提示只要求人工确认引用是否仍支持新表述，不声称引用已经错误。

## 安全与上限

- 单篇最多读取 2 MB，最多对齐 240 个 commit。
- 来源 commit 位于读取窗口外时，只显示 blame 身份，不伪造完整 commit 元数据。
- 来源跳转使用只读版本对比；镜头本身不恢复、暂存、提交、写 Git notes 或移动 Git 状态。
- “标记当前内容已人工复查”只更新插件本地复查点。
- `Esc` 立即关闭镜头，避免来源标记常驻干扰正常写作。
